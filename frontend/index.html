Deployment notes

The browser module requires no build step. The Python service targets FastAPI with Uvicorn. The TypeScript service targets Node.js with built-in HTTP primitives. The Java service uses the JDK HTTP server, avoiding external dependencies for the reference implementation.

Methodology and Sources

Design decisions are recorded here so reviewers can audit the reasoning without relying on unstated assumptions.

Algorithm selection

Dynamic programming was chosen for explicit parent reconstruction and deterministic tie handling. The recurrence stores L[i] = 1 + max L[j] for all j < i where input[j] < input[i]. When multiple predecessors yield the same length, the later predecessor is retained. This tie rule favors lower tail values and aligns with the showcase fixture set.

Interface architecture

The presentation layer is deliberately consolidated into one HTML document. This minimizes deployment friction, preserves portability, and demonstrates that advanced interaction design can be delivered without a build pipeline. Embedded backend code is exposed as copyable source assets rather than executed in the browser, because browser sandboxes do not host Python or JVM processes.

Verification posture

The embedded test matrix checks function presence, return type, and exact fixture outputs. The fixture set includes sequences with multiple candidate subsequences so reconstruction behavior is observable rather than implied.
